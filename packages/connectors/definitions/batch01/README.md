# Batch01 official API definitions

Thirty source candidates from the dated ChatGPT display-name inventory: fifteen Popular, then fifteen work/data providers. These files do not register adapters or change the shared catalog. No tests or provider calls were executed.

`providers.json` contains existing Go `Manifest` / `OperationManifest` serialized field names, closed JSON input schemas and separate review metadata. `test-cases.json` contains designed synthetic cases for the eventual actual HTTPAdapter/schema wrapper. `research.json` records official endpoint/auth references, integration gates and six uncounted reserves.

The integration must compile/review finite descriptors into the normal shared adapter path. Schema checks run before Preview and Invoke; caller arguments cannot select an origin, method, path template, header, version, GraphQL document, raw body shape or response projection. BodyJSON remains a closed typed object. No generic request/raw operation, dynamic endpoint fallback or automatic page following is allowed.

All operations are read-only with one attempt and a four MiB response ceiling. Required fixed revision/version headers and GraphQL error checks are explicit metadata because existing Manifest has no arbitrary header field. Pending integration must not silently omit them. Returned URLs are never followed. Output projection is finite and must exclude unrelated/secret fields; it is not permission to fetch attachments.

BYO token/access-token support is distinct from common OAuth registration or a real lifecycle test. New providers are unavailable until root integrates and qualifies them. Public distribution/legal/API entitlement requirements remain vendor gates. No common OAuth rows or credentials are added here.
