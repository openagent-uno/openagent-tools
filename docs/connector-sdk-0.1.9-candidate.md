# SDK 0.1.9 patch candidate

This source candidate is not a published or remotely qualified SDK release. The public SDK 0.1.8 and its receipts remain unchanged. The catalog retains 114 official connectors plus Custom MCP, the same operations, schemas and permissions.

Outlook Calendar `calendars.list` and `calendars.get` additionally request `canShare` in their fixed Graph projection. Microsoft documents `canEdit` as also applying to shared writable calendars, while `canShare` is true only for the calendar creator. This provides provider metadata that a host can use when selecting an explicitly authorized QA target without resolving account email aliases. It does not authorize a write: the current connection, scopes, host write policy and tool grant still apply. False is preserved, absence stays absent, and a nonboolean value is rejected. No profile endpoint, caller-selected projection or new scope is added. See the [Microsoft calendar resource contract](https://learn.microsoft.com/en-us/graph/api/resources/calendar?view=graph-rest-1.0).

This patch also includes the already committed broker startup correction `975d9426b1373b1db0c1b7f75d329451f3cf5d75`: only Shopify receives a synthetic shop during startup configuration validation. Published SDK 0.1.8 `connector-auth` fails startup when configured with Google Calendar or the four Microsoft providers because those providers correctly reject the unrelated shop context. The deployed broker already carries the correction; source/binary consumers need a new immutable patch release. The standalone connector runner and own-app loopback `LocalOAuth` do not use the broken broker startup path.

Compatibility: existing operation names, arguments, risks, scopes, catalog entries and write paths are unchanged. Calendar read results may contain the additional optional boolean. An old calendar continuation whose embedded `$select` lacks `canShare` is deliberately rejected after upgrade; restart that bounded listing from its first page. There is no automatic replay or resync. Product releases pinned to SDK 0.1.8 do not acquire this behavior until their SDK pin is explicitly updated.

The 0.1.9 qualifier retains all 0.1.8 cohort, source Python catalog parity, definition, privacy, installed metadata and native guards. Designed fixtures check both calendar routes, owned/shared/missing/malformed metadata, fixed projection and unchanged read scope, and rejection of caller-supplied ownership/select fields. Release tags, assets, provider grants, live calendar writes and SharePoint access have not been produced by this source change.
