# Compiled read-only connector batches

This is the source contract for the reviewed batch consumer, not a release or live-provider qualification announcement. Definitions are compiled into the SDK from `packages/connectors/definitions/batch*/providers.json`. They are never downloaded from user-selected URLs. An unsupported definition fails admission; its catalog metadata is not used to advertise a working adapter.

Each provider definition includes the normal catalog item and HTTP Manifest, primary authentication/API references, manual-token permissions, and an operation-specific response contract. All operations are typed reads with fixed origins, paths, credential headers and optional static version headers. GET and closed JSON POST are supported. A GraphQL POST additionally requires a compiled query-only document, closed variables and an application-error check; callers cannot supply a document, operation name, URL or header. Mutation, subscription and introspection documents are rejected. The general HTTP adapter's raw operations are not exposed by this consumer.

## Authentication and setup

The supported authentication mode is `manual_token`. Common OAuth and automatic app registration remain disabled. Hosts retain the user's credential and choose the authorized connection; a model cannot replace that account or configure another origin. Connection configuration is empty for this fixed-origin subset. Provider-specific dynamic tenant origins require a separate reviewed adapter rather than a permissive fallback.

Catalog setup guidance is derived from the compiled authentication documentation and permission description. Users supply only the credential value, without the header's compiled scheme prefix. Basic authentication, where explicitly documented by a definition, requires the documented preencoded Base64 value rather than an invented username/password convention. An omitted credential header/scheme delegates those choices to the compiled manifest; an explicitly different credential target is rejected by the credential API. Token expiry/revocation requires replacement through the provider; the catalog does not promise OAuth renewal.

## Request and response boundaries

The same finite JSON-schema subset is checked before Preview and Invoke. It supports closed objects, required keys, bounded strings with supported regular expressions/enum/const, bounded numbers, booleans and bounded arrays/nested objects. Unknown schema constraints are rejected at definition admission, including unsupported composition/ref features. Duplicate JSON keys, unknown invocation keys and invalid connection/workspace/provider/scope bindings are rejected. Static headers cannot override the credential header, cookies, proxy authorization or HTTP framing.

Every request has a cancellable 30-second deadline and one attempt. Plain HTTP clients are cloned with redirects disabled; custom injected transports must preserve the same no-redirect policy. The default SDK transport has no ambient proxy. There is no automatic traversal, origin fallback, credential re-resolution, write retry or mutation escape hatch.

Responses must be successful HTTP200 JSON within the compiled byte bound. A per-invocation capture validates the original JSON before the generic decoder can discard duplicate keys or round integer IDs. Required response paths, optional success flags, provider application errors and GraphQL partial errors are checked. Only finite declared leaf projections are returned; whole object/array leaves, wildcard traversal and undeclared response fields are rejected or omitted. Empty documented lists remain valid. Error bodies and provider request identifiers do not become result data.

A definition may expose a first page only, or one supported scalar cursor. For cursor operations, the raw provider argument is removed from the public tool schema and replaced by `page_token`. Tokens bind the connection, external account, provider, operation, configuration and arguments. An HMAC is derived through the credential's callback-scoped secret access, with a hash of redacted credential metadata including version/expiry/header. Changing token contents, credential secret or version invalidates it. The signing material is never returned. A restart with the same credential still accepts the token. Preview checks structure and public binding without resolving a credential; Invoke verifies the signature before HTTP. Next URLs and cursor-array/last-item selection are unsupported; those definitions use an explicit first-page subset.

## Evidence boundaries

`response-fixtures.json` files distinguish official examples from reduced fixtures based on official response schemas. Synthetic/public fixture values exercise actual adapter Preview/Invoke with a transport spy, fixed request targets, projection and error boundaries. They do **not** prove credential eligibility, subscription availability, a live provider response or OAuth consent. Missing documented examples are recorded explicitly; a fixture is never fabricated and labeled as an observed provider result.

The shared fixtures additionally test duplicate JSON, malicious schema/arguments, request/header target changes, HTTP200 application errors, GraphQL document injection/partial failure, cursor tampering/rotation/restart, quota/no-retry behavior and exact large-integer preservation. Heavy builds and suite qualification run on the bounded remote worker; lightweight source and configuration checks may run locally. Remote qualification uses bounded commands such as `go test -p 1 ./providers -run TestReviewed -count=1`; the complete canonical release gate still follows the final source freeze.

Manual API/access tokens do not attest OAuth scopes. The reviewed manual-token adapters expose only their compiled read allowlist with `RequiredScopes=[]`; vendor permission names remain setup requirements in `authentication.permissions`. The provider still checks the token's actual permissions: HTTP 403 is a failure and is never retried or reported as an empty successful read. Existing OAuth adapters keep their scope checks.
